HWT101 V3.11 - SAFE LINK PROVIDERS

Este parche corrige el problema nuevo:

  board-k3v2oem1.c: k3_mhl_data incomplete type
  MHL_GPIO_RESET / WAKE_UP / INT undeclared
  MHL_SII9244_* undeclared

Causa:
V3.10 podía copiar un .c completo del donor encima de un .c ya existente
en S10 si ese archivo contenía un símbolo faltante. Eso es peligroso con
arch/arm/mach-k3v2/board-k3v2oem1.c porque el board del donor y el board S10
no usan exactamente la misma API MHL.

V3.11:
- busca primero si S10 YA tiene una definición real del símbolo y fuerza ese objeto;
- NUNCA sobrescribe un .c que ya exista en S10;
- NUNCA sobrescribe un header que ya exista en S10;
- sólo importa del donor fuentes/headers que realmente falten;
- si un símbolo sólo existe dentro de un archivo donor que colisiona con un
  archivo S10 existente, se detiene con exit 88 y lo reporta. No rompe el board.

Reemplaza/agrega solamente:
  scripts/import_link_providers.py
  scripts/import_huawei_v3.sh
  oem_recovered/display/sn65dsi83_hwt101.c

No cambies YAML.

Si termina con exit 88, comparte LINK-PROVIDER-IMPORT.txt. Ese reporte nos
dirá qué símbolo necesita una extracción quirúrgica en vez de reemplazar
todo board-k3v2oem1.c.
